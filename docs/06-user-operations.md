# 用户操作文档 v0.1

本文档记录当前 MVP 的用户侧操作方式和已经确认的产品结论。后续每完成一个功能或确认一个重要结论，都应同步补充到这里。

## 工作台布局

当前采用桌面工具型布局：左侧为功能导航，右侧为对应工作区。已可用模块包括：

- `AI 智能混剪`
- `视频混剪`
- `智能分割`
- `素材仓库`
- `产出记录`

未完成模块在左侧导航中置灰，避免误导用户。

## 视频混剪

视频混剪用于导入素材后批量生成混剪视频。当前支持三种模式：

- `自定义模式`：用户直接选择素材、设置数量、比例、字幕、音量、BGM、水印等参数后导出。
- `文案模式`：用户添加一条或多条文案，系统按文案自动合成语音，再按文案分组生成视频。
- `音频模式`：用户上传一条或多条音频，系统按音频时长自动选择素材并生成视频。

文案模式和音频模式下，字幕应由文案或音频描述生成，不需要再走自动 ASR；字幕仍保留开关，用户可选择是否烧录到视频中。

## AI 智能混剪

AI 智能混剪用于“写文案，它做视频”的场景。用户输入文案或上传音频后，系统会：

1. 分析素材仓库并生成片段库。
2. 对片段关键帧建立本地向量索引。
3. 根据文案或音频描述匹配最相关画面。
4. 沿用现有语音合成、字幕样式和导出流程生成成片。

当前路线是本地 ONNX 向量匹配，不依赖在线视频理解 API。API 视频理解可作为未来增强，不作为 MVP 主线。

## 素材仓库

素材仓库用于管理输入资产，不等同于产出记录。当前第一版支持添加本地素材目录或单个素材文件，系统只记录路径，不复制或移动原文件。

素材分类包括：

- `原始素材`：拍摄原片、直播原片、口播长视频。
- `分割片段`：智能分割生成的可复用片段。
- `成品复用`：外部成片或产出记录中需要二次混剪的视频。
- `音频素材`：配音、口播音频、BGM 等音频文件。

素材仓库会扫描文件名、路径、时长、大小、分辨率、横竖屏、有无音频和修改时间。路径被移动或删除时，素材源会标记为失效，但不会删除用户真实文件。

素材仓库索引保存到本地 SQLite：`web/_run/ecutauto.db`。页面初次进入只读取索引；点击 `刷新索引` 才会重新扫描文件，避免素材量大时每次打开都卡顿。旧版 `web/_run/material_library.json` 只作为兼容迁移来源。

素材仓库和产出记录的关系：

- 素材仓库管理“输入资产”，服务混剪、智能分割和 AI 智能混剪。
- 产出记录管理“生成结果”，按日期、批次和 manifest 浏览成片。
- 智能分割结果会自动进入素材仓库的 `分割片段`。
- 产出记录中的单个成片或批次目录可通过入库按钮进入 `成品复用`。
- 视频混剪、AI 智能混剪和智能分割可通过左侧 `素材仓库` 按钮选择已有素材源。
- 选择素材来源时支持按分类、横竖屏方向和名称/路径搜索筛选。AI 智能混剪默认筛选 `分割片段`，智能分割默认筛选 `原始素材`。

## 智能分割

智能分割用于把长视频或素材仓库拆成可复用片段。当前支持导入素材文件夹或单个视频文件。

分割模式分为两种：

- `原始素材`：适合原始拍摄素材、口播原片、产品展示、探店、vlog 原片。系统会尽量按镜头边界素材化。
- `成片复用`：适合已经剪过、包含转场或多场景的视频。系统会合并频繁转场，只在目标时长附近保守切分，避免 AI 混剪时画面过碎。

如果视频是一镜到底口播或直播，不能只靠镜头检测；系统会结合目标时长、最大时长和语音保护进行拆分。语音保护用于尽量避开人声中间切断。

## 产出记录

产出记录模块用于浏览本地生成结果。当前会扫描默认导出目录：

```text
web/_run/exports/YYYY-MM-DD/批次目录/
```

页面按日期、批次和视频文件展示。点击视频后可在中间区域播放，右侧显示文件名、大小、修改时间、生成模式、批次目录、视频路径和 `manifest.json` 路径。

用户也可以添加外部导出根目录。添加和移除只是管理作品库记录，不会删除真实文件。Web MVP 阶段通过手动输入本地目录路径完成；打包成 Tauri 桌面端后，可升级为系统文件夹选择框和“在 Finder 中打开目录”。

## 导出分辨率

当前默认导出清晰度为 `1080P`：

- `9:16` 输出 `1080x1920`。
- `16:9` 输出 `1920x1080`。
- `跟随素材方向` 会先按素材多数方向解析为 `9:16` 或 `16:9`，再套用对应 1080P 画布。

可选 `720P` 轻量导出：

- `9:16` 输出 `720x1280`。
- `16:9` 输出 `1280x720`。

不默认使用原始分辨率。混剪素材可能横竖和尺寸不一致，最终成片需要固定画布，便于平台上传和批量复用。

导出画质分为三档：

- `标准`：导出更快，文件较小，适合测试。
- `高清`：默认档位，画质和速度相对均衡。
- `高质量`：更清晰，文件更大，导出更慢，适合最终成片。

分辨率和画质属于导出参数，不放在视频预览顶部。用户点击 `开始生成` 后，在导出抽屉的确认阶段调整，确认后再开始生成。

## 输出目录规则

默认导出结构：

```text
exports/
  2026-06-28/
    115000_模式_任务名/
      manifest.json
      成片_01.mp4
```

文案模式和音频模式按条目分组更清晰：

```text
文案01_xxx/成片_01.mp4
音频01_xxx/成片_01.mp4
```

自定义模式直接放在批次目录下即可，因为它没有天然的文案或音频分组。

## 桌面端与 Web MVP

当前 Web MVP 可以通过本地 Node 后端读取用户输入的目录路径，但浏览器页面不能直接弹出系统级文件夹选择框，也不能自由访问任意目录。

开发期推荐 Node `22.x`，以保证原生 SQLite 依赖、Vite 和本地后端行为稳定一致。`package.json` 允许 `>=22 <27`，兼容当前 Node 24 和后续桌面打包环境。进入 `web/` 后可用 `nvm use` 读取 `.nvmrc`。

打包成 Tauri 桌面端后，应补齐这些原生能力：

- 点击按钮选择文件夹。
- 点击按钮打开导出目录。
- 记住多个常用目录。
- 后续可监听目录变化。

现阶段不需要因为目录选择能力提前改架构，Web 端的目录记录逻辑可以继续复用。

## 后续需要继续记录

- 字幕样式：字体、字号、颜色、描边、位置和自定义文字的操作说明。
- 水印能力：去水印区域、图片水印、视频水印的拖拽和缩放说明。
- 音频设置：原视频音量、BGM 音量、试听和混音规则。
- 语音合成：音色筛选、试听、合成失败时的处理方式。
- 模型管理：TransNetV2、sherpa-onnx、Chinese-CLIP 的下载和缺失提示。

# 高光切片设计记录

本文记录高光切片模块的产品边界、切分流程和输出规范，供后续开发与用户侧说明复用。

## 模块定位

高光切片用于从长视频中提取适合单独发布的精彩片段。它不同于智能分割：

- 智能分割：按镜头变化和人声保护把素材拆成可复用片段。
- 高光切片：按字幕语义理解内容，找到完整话题、评分、生成标题，并整理成分组。

## 切分流程

切分过程参考 AutoClip 的字幕语义切片思路，但保留本项目的 Node 后端和本地工作台架构。

1. 素材准备：读取本地视频，优先使用指定 SRT 或同名 SRT；没有字幕时可自动识别。
2. 内容分析：按字幕文本提取话题大纲和关键信息。
3. 时间线提取：根据话题在字幕中定位自然的开始和结束时间。
4. 精彩评分：按信息价值、情绪共鸣、传播潜力和结构完整性评分。
5. 标题生成：为保留片段生成短视频标题和推荐理由。
6. 合集推荐：按主题把相关片段整理成分组。
7. 视频生成：默认只生成单个高光片段，合集视频后续作为可选动作。

## 输出规范

高光切片输出采用“片段 + 分组目录”的方式：

```text
高光切片批次/
  clips/
    01_片段标题.mp4
    02_片段标题.mp4
  collections/
    01_主题分组/
      collection.json
      clips.txt
  manifest.json
```

`clips/` 保存真实切片视频。`collections/` 保存 AI 推荐的主题分组，不默认拼接成新视频，避免重复占用空间和产出记录混乱。

`collection.json` 记录该分组包含的片段标题、路径、评分、时间段和推荐理由。`clips.txt` 用于快速查看本地片段路径。

## 与 AutoClip 的差异

AutoClip 的合集在数据层是 `clip_ids` 分组，但最终会默认拼接为合集视频。本项目不默认拼接：

- 默认形态：合集是分组目录。
- 可选能力：后续增加“生成合集视频”按钮。
- 原因：混剪产品更重视素材复用，分组比重复生成视频更适合后续 AI 智能混剪和素材仓库。

## 可展示处理说明

面向用户可以展示以下说明：

```text
系统会先读取字幕，分析视频中的主要话题，再为每个话题定位自然的开始和结束时间。
随后会根据内容价值、情绪共鸣、传播潜力和结构完整性进行评分，保留达到阈值的片段。
生成后，片段会保存为独立视频；相关片段会整理到分组目录中，方便后续复用或手动生成合集视频。
```

## 性能优化记录

高光切片的耗时通常来自三部分：

- 字幕准备：没有同名 SRT 时，需要先跑 ASR。
- 内容理解：大纲提取、时间线定位、评分标题、合集推荐都需要 LLM 调用。
- 视频生成：FFmpeg 按时间段切片并重新编码。

本机硬件加速主要优化第三部分，即视频生成阶段。后续可增加“导出加速”选项，自动探测 `h264_videotoolbox`、`h264_nvenc`、`h264_qsv`、`h264_amf`，失败时回退 `libx264`。它不能直接加速 LLM，也不能明显加速远程 API 请求。

当前更优先的优化顺序：

1. 优先复用同名 SRT 或 ASR 缓存，避免重复识别。
2. 增加任务记录，统计每次生成总耗时和产出数量。
3. 控制 `maxClips`、`maxCollections` 和分析文本长度，减少 LLM 轮次。
4. 再接入硬件编码，降低大量片段导出时的等待时间。
